# 우리가 만드는 스마트워크 랩 (SmartWork Lab)

우만종합사회복지관의 모든 스마트워크 웹앱을 **검색·실행·유지보수·개선·분석**할 수 있는 통합 운영 플랫폼입니다.

직원은 필요한 웹앱을 쉽게 찾아 이용하고, 관리자는 운영·유지보수·개선 요청·AI 분석을 하나의 시스템에서 수행합니다. 스마트워크 웹앱이 계속 늘어나도 손쉽게 등록·관리할 수 있는 **확장 가능한 구조**를 목표로 합니다.

---

## ✨ 주요 기능

| 영역 | 기능 |
|--|--|
| **웹앱 관리** | 등록 · 수정 · 삭제 · 카테고리/태그 분류 · 상태(운영중/점검중/종료) · 버전 · 담당자 |
| **검색** | 통합 검색 · 카테고리/태그 필터 · 카드형/목록형 전환 · 즐겨찾기 |
| **대시보드** | 전체/운영/점검 현황 · 인기 웹앱 · 카테고리 분포 · 공지 · 처리 대기 · 유지보수 일정 |
| **유지보수** | 점검 일정(예정/진행/완료) · 체크리스트 · 담당자 |
| **개선요청** | 직원 등록 → 접수/검토중/반영예정/완료 상태 관리 |
| **오류신고** | 신고 등록 · 화면 캡처 · 우선순위 · 처리 이력 |
| **공지사항** | 관리자 작성/고정, 직원 조회 |
| **AI 운영 분석** | 사용량 분석 · 유지보수 우선순위 · 개선 아이디어 · 월간 리포트 자동 생성 (참고용) |
| **감사 로그** | 모든 관리자 작업 기록 |

## 🚀 빠른 시작

```bash
cd smartwork-lab
npm install
npm run dev
# http://localhost:3000
```

> **환경 변수 없이도 바로 실행됩니다.** Supabase/OpenAI 키가 없으면 자동으로
> **데모 모드**로 동작하며, 내장 시드 데이터로 모든 화면을 확인할 수 있습니다.
> 로그인 화면에서 **관리자 / 일반 직원** 역할을 선택해 권한별 화면을 둘러보세요.

### 운영 모드 연결

1. `.env.example` 을 `.env.local` 로 복사하고 값을 채웁니다.
2. Supabase 프로젝트에서 `supabase/schema.sql` → `supabase/seed.sql` 순서로 실행합니다.
3. Supabase Auth 에서 **Google** 공급자를 활성화하고 리다이렉트 URL(`/api/auth/callback`)을 등록합니다.
4. `NEXT_PUBLIC_SUPABASE_URL` 이 설정되면 실제 Google 로그인과 DB 연동이 활성화됩니다.

```
smartwork-lab/
├── src/
│   ├── app/

│   │   │   ├── dashboard/        # 메인 대시보드
│   │   │   ├── apps/             # 웹앱 목록 + [id] 상세
│   │   │   ├── favorites/        # 즐겨찾기
│   │   │   ├── notices/          # 공지사항
│   │   │   ├── improvements/     # 개선요청
│   │   │   ├── errors/           # 오류신고
│   │   │   ├── maintenance/      # 유지보수 (관리자)
│   │   │   ├── admin/            # 웹앱 관리 (관리자)
│   │   │   ├── ai/               # AI 운영 분석 (관리자)
│   │   │   └── logs/             # 감사 로그 (관리자)
│   │   ├── login/                # 로그인 (Google / 데모)
│   │   ├── api/auth/             # Google OAuth 시작·콜백
│   │   └── layout.tsx
│   ├── components/               # UI · 레이아웃 · 도메인 컴포넌트
│   ├── lib/
│   │   ├── types.ts              # 도메인 타입 (스키마와 1:1)
│   │   ├── data.ts               # 데이터 접근 계층 (Supabase/데모 폴백)
│   │   ├── seed.ts               # 데모 시드 데이터
│   │   ├── actions.ts            # 서버 액션 (인증/등록/상태변경)
│   │   ├── session.ts            # 세션/권한
│   │   ├── ai.ts                 # AI 분석 엔진
│   │   ├── labels.ts             # 상태 한글 라벨/색상
│   │   └── supabase/             # 브라우저·서버 클라이언트
│   └── middleware.ts             # 로그인 가드
└── supabase/
    ├── schema.sql               # 테이블 + RLS(권한 기반 접근 제어)
    └── seed.sql                 # 초기 데이터
```

### 확장 포인트 — 새 스마트워크 웹앱 추가

- **화면에서**: 관리자 → *웹앱 관리* → *새 웹앱 등록* (URL 검증·중복 방지·필수 입력 검증 내장)
- **메뉴 추가**: `src/components/layout/nav.ts` 에 항목만 추가
- **데이터 소스 교체**: `src/lib/data.ts` 의 함수 내부를 Supabase 쿼리로 바꾸면 화면 코드는 그대로 동작

## 🔐 보안 · 윤리 원칙

- **권한 기반 접근 제어**: 미들웨어 가드 + Supabase **RLS** 정책 (`is_admin()`)로 관리자/직원 분리
- **최소 개인정보**: Google 로그인만 사용, 외부 회원가입·불필요한 개인정보 수집 없음
- **감사 로그**: 모든 관리자 작업 기록
- **AI 윤리**: AI 결과는 **운영 개선 참고용**이며 **직원 평가 목적으로 사용하지 않음**, 자동 의사결정 없음
